## Gate 8 Objective

Make the accepted Gate 6 history useful to authorized staff through explicit read-only projections while preserving the Nelson lifecycle as the only forward operational path. Gate 8 is parity scaffolding, not redesign, data correction, canonical reference acceptance, or migration cutover.

Every packet must retain literal source assertions, deterministic provenance, missing/broken evidence flags, private-media authorization, and an unmistakable historical/non-operational presentation. No packet may create current Applications, liabilities, receipts, permits, clearances, Users, or workflow tasks.

Each Gate 8 packet must include focused feature tests, authorization tests, query-count or query-plan evidence where relevant, browser checks against `bpls_ipil_parity_gate6_20260911`, and before/after `ipil:audit` results. The minimum invariant set remains:

## Explicitly Outside Gate 8

- broad UI redesign or simplification;
- identity deduplication or collision resolution;
- PSGC barangay or LOB mapping acceptance;
- historical amount/status/data correction;
- current policy or Price recalculation over history;
- account claiming or historical Owner-to-User conversion;
- live Ipil access, culling, reseeding, Cloud/R2 movement, deployment, cutover, or source write-back.

## Stop Conditions

Stop a packet if it requires a guessed identity/reference mapping, converts a claim into current authority, hides an orphan/duplicate/contradiction, exposes taxpayer data beyond the authorized role, makes historical records actionable, changes a Gate 6 anchor, or needs an unapproved official-report meaning. A successful packet advances only its named projection; it does not authorize the next packet automatically.
